# 新用户第一天走查（2026-10-05）

用已安装的 mod（0.1.2）在全新会话里，以一个真实用户的方式走完第一天，记下卡点和体验问题；修复后用 0.1.3、0.1.4 在新的空白档案里复走一遍核对。

## 怎么做的

- **人物（合成，未用任何真实数据）**：林晓峰，36 岁，杭州后端工程师，久坐。两份体检报告（2025-10-18、2026-09-12，各 60 余项，含超声、低剂量 CT 叙述和总检结论；中度脂肪肝、ALT/GGT 升高、尿酸 512、血脂异常、维生素 D 缺乏、甲状腺结节 C-TIRADS 3、肺微结节 Lung-RADS 2），用 Chrome 打印成真实样式的 PDF；一年的 Apple Watch 数据，按中文 iPhone 的样子导出成 `导出.zip`（内含 `导出.xml`）；他父亲（64 岁）一份血糖达糖尿病范围的报告。
- **环境**：170×50 终端，空白 `LONGPI_HOME`，不设 `LONGEVITY_SKILLS_HOME`，项目里关掉 life-coach。像真人一样先写了会儿代码，再想起装过 LongPi；用鼠标点面板（SGR 鼠标事件），把文件路径"拖"进对话。
- 截屏和调试日志在会话的临时目录里，没有进仓库。

## 已按默认处理（可否决，0.2.0）

1. **甲状腺 / 乳腺结节的分级**：TI-RADS 1–2 不再生成任何步骤；TI-RADS 3 改为「按报告建议复查」，不再是「最重要的一步」，只有结节 ≥2.5 cm 或报告没写大小时才仍提示就诊；TI-RADS 4 及以上照旧提示就诊。BI-RADS 1–2 无步骤，3 为约 6 个月复查，4 及以上就诊。依据：C-TIRADS 2020 对 3 类不建议穿刺，4A ≥1.5 cm、4B 及以上 ≥1.0 cm 才建议；ACR TI-RADS 对 TR3 ≥2.5 cm 建议穿刺（两套标准的对照见 Dong 等，QIMS 2023）。同时修了结节大小只认毫米、不认厘米的解析问题。
2. **方案的证据库补了肝和尿酸**：在 mod 自己的 `data/reference-extra.json` 里加了三个指标（ALT、GGT、尿酸，个体内变异分别引自 EuBIVAS 2017 摘要和 EFLM 数据库元分析）和两条试验证据：减重使 ALT 平均下降 9.81 U/L（Koutoukidis 等，JAMA Intern Med 2019，22 项随机试验）、DASH 饮食使血尿酸下降 0.35 mg/dL（Juraschek 等，Arthritis Rheumatol 2016）。每个数字都附原文摘要里的句子。方法库更新后已有的条目以方法库为准；这些条目也适合提交回 longevity-skills。顺带修了方案比较单位时把 μmol/L 和 umol/L 当成不同单位的问题。
3. **医生简报**：新增「报告上其他需要一起看的」一节，列出同一份报告里超出参考范围的数值和不是「未见异常」的检查结论（爸爸的血压、LDL、颈动脉斑块会自动写上）。
4. **「一起研究」**：没点过「加入」时显示「未加入」。
5. **日常存在感**：每天第一次有空的时候，输入框上方出现一行「LongPi · 今天：<今天的三件事里第一件没做的>」[打开][稍后]，10 分钟后自己收起，一天一次，演示模式下不出现。
6. **按名称取数算作已核对**：本机档案里，按化验名称对上、单位和数值范围都核对过的结果算「已核对」。这也让「真的年轻了」的说法在证据够时可以出现，符合你之前「把好消息讲清楚」的要求。

## 小问题（记下，未改）

- 「和你有关」的研究卡，「和你的关系」都是同一句「你的记录算过这一项，结果在健康页上」，没有写他自己的结果。
- 超声和 CT 的叙述存进记录时被截断（Pi 自己说了「后半段被截断，以 PDF 原件为准」）。
- 选「晚饭提前」时，系统还以为他没有手环（首次打开长寿图鉴时序列还没刷新）。
- `claude -p` 里没人能回答同意对话框，第一次存数值会被拒绝；需要先在 `/longpi` 里同意。

## 第二轮：真实材料（同一天，0.1.6 → 0.1.8）

用主人自己提供的真实材料，在一个单独的私有测试档案里（不碰本人的 `~/.longpi`）走了一遍：三份体检（12–22 页，同一品牌两家分院，跨三年）、一份消费级基因检测报告（微基因叙述版，2924 页、261 MB）、一年的 Apple Watch 导出（`导出.zip`，解压后 XML 500 MB，另有 313 MB 的临床记录文件、运动轨迹和心电图）。这里不记任何个人数值。

**顺利的**
- 一条消息拖进三份体检：Claude 用文字提取读完，分三次录入；第一次录入前弹出同意框（0.1.4 起）。
- 分诊抓住了三次体检里持续下降的一组红细胞指标，建议 1–2 周内看全科或血液科，不自己补铁；后续回复里「这周就一件事」保持不变。
- 手表导出：15 万多条原始记录，9 秒、约 120 MB 内存转换完，导入 2222 条每日数值，中文文件名没问题。
- 合并后的庆祝动画只弹一次（站点、Pi 长大、奖章同在一张）。

**修了的**
- 基因报告在 mod 里存不进去：核心的做法要 PyMuPDF 和同步子进程。新工具 `import_genetic_report` 用 macOS 自带的 PDFKit 只打开目录里关键性状对应的 57 页（约 3 秒），存下 14 个位点和单倍群，附核心原有的局限说明，封面姓名不保存。位点表在 PDFKit 里是一行一条，解析器补了这种格式。
- 导出当天的步数、活动消耗只到导出那一刻，导入时不再当成一整天（否则会出现「今天 70 步」）。
- 年龄和性别没填时，需要看医生的卡片只在顶部横幅里一行带过；现在排在设置步骤上面。
- 「今天的三件事」：记录要求先看医生时，第一件是「约医生」，「起草方案」等看完医生再说。
- 「10~9/L」这类报告原样单位显示成 ×10⁹/L；长寿图鉴因缺年龄关闭时，加了「去填年龄」按钮。

**记下的**
- 更正：上一版写「腹部 B 超没录进档案」是我核对时的错误（筛选时漏掉了以数字开头的数值）。它录进去了，问题在显示：「报告里的叙述」只认带「超声」的行。现在彩超、CT、X 线等检查结论都会进入叙述，并按各自日期保存。
- 录入完整度另加了一道核对（0.2.0）：录入时把报告路径传给 `report`，LongPi 用 PDFKit 读报告每一页，把还没录的检查和化验项目列回给 Claude 补录，每份报告最多核对两轮。在三份真实报告上，只找出了 2023、2024 年的眼底检查没录。
- 报告只在封面印年龄（不标注是年龄），Pi 正确地请本人确认。
